# Состояние реализации RustClip 0.1

Проект создан по принципу белой комнаты. Использованы механизмы Windows. Репозиторий содержит GPLv3, Cargo объявляет GPL-3.0-or-later.

## Реализовано

- Win32 `AddClipboardFormatListener` и проверка sequence number; чтение Clipboard в отдельном потоке, ограниченные повторные попытки открытия.
- Разрешённые форматы: Unicode/ANSI/OEM text, DIB/DIBV5, CF_HDROP, locale, зарегистрированные HTML Format, Rich Text Format и PNG. Сохраняются байты разрешённых представлений; неизвестные форматы не читаются.
- Встроенные точные исключения проблемных форматов, пользовательские дополнительные исключения по имени/ID. Три неуточнённых названия из снимков не угадываются.
- CVIF и ExcludeClipboardContentFromMonitorProcessing исключают захват; CanIncludeInClipboardHistory=0 исключает сохранение. Собственный RustClip/Owner предотвращает запись собственных операций.
- Отдельные исключения захвата и hotkeys по имени exe или полному пути (без wildcard).
- Долговременная история в отдельных файлах JSON; запись через временный файл и rename; сообщения об ошибках чтения/записи.
- Сравнение содержимого с последними N клипами; лимит количества незакреплённых записей. Лимит применяется сразу.
- Настраиваемые глобальные сочетания для открытия истории, предыдущего/следующего клипа и вставки текста; повторная регистрация через Windows `RegisterHotKey` после сохранения настроек, проверка дубликатов и сообщение о конфликте; single-instance mutex и передача команды открытия второму запуску.
- Центральное Win32-превью текста и растровых изображений, topmost/no-activate, монитор целевого окна; таймер, Esc; сохранение пропорций изображения.
- Вставка после отпускания модификаторов, Ctrl+V либо Shift+Insert, возврат фокуса, восстановление прежнего поддерживаемого Clipboard с проверкой sequence number.
- История, поиск по тексту/источнику/ярлыку, звёздочки и фильтр звёздочек, удаление с защитой отмеченных записей.
- Вкладка текстовых шаблонов, создание из клипа, plain-text редактор с предупреждением потери форматирования.
- Настройки мониторинга, фильтров, порядка истории, дедупликации, лимитов, вставки и таймера превью.
- Трей: открыть/выход; закрытие главного окна скрывает его; сохранение настроек на выходе.
- Экспорт выбранного клипа в UTF-8 TXT/PNG, создание JSON backup всей текущей истории и настроек.
- Светлая тема, русские меню, жёлтый заголовок и навигация слева в настройках.
- Настройки и редактор клипа открываются в отдельных окнах Windows; они больше не накладываются внутри главного окна.

## Пока отсутствует / отличается от спецификации

- Точный оригинальный UI: главное превью пока встроено справа, не отдельная карточка у основного окна; центральное превью упрощено, без оригинального шаблона заголовка/номера позиции. Это не пиксельная копия.
- Редактируемые глобальные комбинации и буквенно-цифровые shortcuts строк; mouse hold и hot corners.
- Полное дерево шаблонов, папки, макросы, несколько баз, RTF-редактор.
- Шифрование, пароль/блокировка, in-memory база, SQLite/FTS, отложенная загрузка больших blob.
- Восстановление backup через интерфейс, расписание/ротация backup.
- Расширенный поиск с `%`, задержка/порог поиска, несколько ярлыков на клип, полный мастер очистки.
- Множественная вставка и разделители, smart capture, посимвольная печать, оригинальный URL/browser actions.
- Автозагрузка, звук, смена языка, настройка шрифтов/цветов, проверка обновлений, учебный мастер.
- Подтверждение выхода и удаления; история хранится в памяти, поэтому 50000 больших изображений пока неприемлемы.

## Ограничения текущего ядра

- Для чтения нативного изображения используется arboard после raw capture. Это дополнительное чтение; изменение Clipboard между этапами отбрасывает результат по sequence number.
- Ограничения: до 32 MiB на представление и 64 MiB суммарно, по умолчанию 100 KiB Unicode-текста. Большие/неподдерживаемые представления могут отсутствовать.
- Восстановление Clipboard ограничено поддержанными форматами и текущими лимитами. Это не точная копия всех возможных OLE/приватных форматов.
- Восстановление после вставки использует задержку; фактическое завершение чтения целевым приложением не подтверждается. Приложения с повышенными правами могут отвергать ввод. Сообщение об ошибке доступно в главном окне.
- Синхронный GetClipboardData не имеет жёсткого прерываемого timeout. Worker может задержаться на проблемном источнике; UI при этом отделён.
- Чтение истории и сохранение файлов выполняется UI-потоком; потребуется вынести I/O в хранилище перед использованием многогигабайтных баз.
- Повторное нажатие на границе истории остаётся на крайнем клипе. Это выбранное поведение RustClip, а не проверенное поведение оригинала.

## Проверено

- `cargo check --offline` прошёл.
- Тесты: обратная совместимость настроек, дедупликация форматов, Unicode/нулевой терминатор, точное сопоставление exe, повреждённый CF_HDROP и несколько путей.
- Демонстрационный запуск: окно создаётся, процесс отвечает, русские строки отображаются. По снимку исправлен фон основной области.
- Вставка в сторонние приложения, конфликт горячих клавиш, захват фотографий и реальная работа скрытого окна пока не подтверждены сквозным тестом. Наличие кода и успешная компиляция не заменяют эти проверки.

## Следующие приёмочные проверки

1. Запустить RustClip и убедиться, что регистрация клавиш успешна.
2. В тестовом редакторе скопировать A/B/C, скрыть RustClip, выбрать клип через Ctrl+Shift+Up, отпустить клавиши; проверить превью, вставку и последующий Ctrl+V.
3. Повторить с изображением из Snipping Tool и вставкой в Paint.
4. Во время отложенного восстановления скопировать новый текст; он не должен быть перезаписан старым Clipboard.
5. Перезапустить RustClip, проверить историю, шаблоны и звёздочки; проверить экспорт и backup на тестовых записях.

# Clipdiary 5.7: функциональная и визуальная спецификация

Дата исследования: 16 октября 2026. Исследована установленная локально русская версия Clipdiary 5.7. Документ предназначен как исходная спецификация для последующей реализации аналога на Rust.

## 1. Границы исследования

Обозначения достоверности:

- **Проверено** — наблюдалось в установленном приложении или прочитано из его активной конфигурации.
- **Подтверждено документацией** — указано на официальном сайте Clipdiary.
- **Предположение** — наиболее вероятное поведение, которое следует подтвердить отдельным ручным тестом перед реализацией.
- **Ресурс 5.7** — название/подсказка из установленного `Languages/messages.pot` (2021-12-12). Подтверждает предусмотренную функцию, но не её текущее значение, доступность и точную геометрию UI.
- **Проектное решение** — предложение для Rust, а не наблюдение о Clipdiary. Разделы 13, 14 и архитектурные части 17 имеют именно этот статус.

Повторный аудит: исправлены смешение задержек захвата/вставки, неверное назначение фильтра hotkeys, неподтверждённые свойства overlay и приписывание CopyQ проектных решений Rust. Функциональный паритет пока не доказан; оставшиеся проверки перечислены в разделе 18.

Исследование не должно копировать закрытый код или формат базы побайтно. Цель — воспроизвести наблюдаемое поведение, UX и совместимость с форматами Windows Clipboard.

## 2. Назначение и основная модель

Clipdiary — фоновый менеджер буфера обмена Windows. Пока процесс запущен, он наблюдает за изменениями системного clipboard и сохраняет самостоятельную долговременную историю. Новый `Copy` не уничтожает старый клип в истории приложения.

Основной цикл:

1. Другое приложение помещает данные в Windows Clipboard.
2. Clipdiary получает уведомление об изменении.
3. После небольшой задержки читает доступные форматы и метаданные источника.
4. Создаёт запись в локальной базе и добавляет её в конец истории.
5. Пользователь вызывает окно или циклически выбирает старый/новый клип горячими клавишами.
6. При вставке Clipdiary временно восстанавливает нужные форматы в Clipboard, активирует прежнее целевое окно и инициирует вставку.

Приложение работает из системного трея, стартует свёрнутым и может запускаться вместе с Windows.

## 3. Поддерживаемые данные

Подтверждены следующие категории:

- обычный Unicode-текст;
- форматированный текст RTF;
- HTML и текст, скопированный из браузера;
- bitmap/скриншоты;
- списки файлов;
- неизвестные или дополнительные clipboard-форматы, которые в списке помечаются знаком вопроса.

Одна запись может содержать несколько представлений одних данных, например HTML + plain text. При вставке желательно восстанавливать весь сохранённый набор форматов, чтобы целевое приложение само выбрало лучший. Для поиска и превью используется безопасное текстовое или растровое представление.

## 4. Горячие клавиши

По пользовательскому снимку страницы горячих клавиш и поздней конфигурации (ранний разбор ID был неточен):

| Действие | Код настройки | Наблюдаемая комбинация |
|---|---:|---|
| открыть историю буфера обмена | `6,6,68` | `Ctrl+Shift+D` |
| предыдущий клип | `2,6,38` | `Ctrl+Shift+Up` |
| более новый клип | `3,6,40` | `Ctrl+Shift+Down` |
| вставить текущее содержимое Clipboard как простой текст | `4,6,86` | `Ctrl+Shift+V` |
| Шаблоны #1 | `7,7,68` | `Ctrl+Shift+Alt+D` |

Важно: пользователь описал комбинации как `Ctrl+D`, `Ctrl+Up`, `Ctrl+Down`, но автоматический тест открыл окно только с добавленным `Shift`. Значение `6` соответствует сумме флагов Windows `MOD_CONTROL (2) + MOD_SHIFT (4)`. Реализация должна брать комбинации из настроек, а не зашивать их в коде. В UI их следует отображать человеческим текстом.

### Предполагаемая машина состояний циклического выбора

- До первого `Previous` курсор истории стоит на текущем clipboard/самом новом клипе.
- `Previous` сдвигает курсор к более старой записи; `Next` — к более новой.
- По ресурсу 5.7 Quick Copy сразу копирует выбранный клип в системный Clipboard. Автоматическая вставка после копирования включена на новом пользовательском снимке; ресурс уточняет, что она выполняется при отпускании клавиш. Фактическую последовательность событий ещё следует проверить.
- Новое внешнее копирование сбрасывает курсор к концу истории.
- На границах возможен стоп или короткий звуковой сигнал; это требует ручной проверки.

Подтверждено пользователем: `Ctrl+Shift+Up/Down` работает, когда главное окно Clipdiary скрыто. После каждого перехода Clipdiary показывает превью выбранного клипа по центру экрана поверх всех остальных окон. Главное окно при этом не открывается, а рабочий контекст пользователя сохраняется.

Синтетический тест не зафиксировал overlay; причина не установлена. Нельзя заключать, что приложение игнорирует синтетический ввод. Возможны влияние фокуса и фильтра горячих клавиш (в нём указан `clipdiary.exe`); нужны контролируемые условия. Пользовательское подтверждение работы функции остаётся действующим.

## 5. Главное окно

### Компоновка

- Обычное Windows-окно с фиолетовой системной строкой заголовка.
- Заголовок: `Clipdiary (История буфера обмена : Все клипы)`.
- Меню: `Файл`, `Клип`, `Вид`, `Ярлыки`, `Помощь`.
- Под меню — toolbar с крупными иконками: операции с клипом, текстовое представление, перемещение вверх/вниз и удаление.
- Вкладки: `История буфера обмена` и `Шаблоны`.
- Основная область — одноколоночный прокручиваемый список.
- Внизу — строка поиска и три кнопки с лупой для направления/режима поиска.

### Строка клипа

Слева направо:

1. Иконка типа (`HTML`, лист текста, палитра/картинка, `?`).
2. Односимвольная синяя клавиша быстрого выбора (`1..0`, затем буквы).
3. Однострочное описание: начало текста либо `Картинка WIDTHxHEIGHT скопировано из SOURCE`.

Самые новые записи находятся внизу. Это подтверждено тестовыми клипами: `RUSTCLIP_TEST_OLDER_TEXT` располагался над `RUSTCLIP_TEST_NEWER_TEXT`. После повторного открытия список может быть прокручен к концу, а активная запись выделяется стандартной синей полосой Windows.

В ресурсе 5.7 есть `Latest clips at the top`: порядок настраивается. Наблюдение «новые внизу» описывает текущий режим, а не неизменное правило.

### Выбор и вставка

- Одинарный щелчок/стрелки меняют выделение и превью.
- Двойной щелчок вставляет выбранный клип в окно, которое было активно до вызова Clipdiary.
- Контекстное меню должно как минимум позволять вставить, скопировать обратно в Clipboard и удалить.
- После вставки окно скрывается (`HideWindowAfter=1`).
- В дереве шаблонов после вставки сворачиваются раскрытые узлы (`CollapseTreeAfterPasting=1`).
- Цифры/буквы рядом со строками работают как быстрый выбор (`UseShortcutsCH=1`, `UseShortcutsSN=1`).

## 6. Превью — критически важное поведение

Превью реализовано отдельным borderless/popup-окном рядом с правой границей главного окна и не занимает ширину списка.

### Текст

Проверено: белая компактная карточка с моноширинным/системным текстом. Она содержит содержимое клипа, разделитель и метаданные:

- `Приложение`;
- `Заголовок`;
- `Ссылка`;
- `Создано: YYYY-MM-DD HH:MM:SS`.

Длинный текст ограничивается областью карточки. Исполнение HTML и точный движок отображения не проверены; безопасный показ без исполнения — требование к Rust.

### Изображение

Проверено: после выбора строки `Картинка 1950x530 скопировано из SnippingTool` появилось отдельное большое превью изображения. Чёрная область может быть частью исходной картинки: цвет фона, масштабирование и обрезка не установлены по этому снимку. Сохранение пропорций и ограничение рабочей областью монитора — требования к Rust, требующие сравнения с оригиналом.

### Превью при `Previous/Next`

Пользователь подтвердил скрытое главное окно и центральное превью поверх остальных окон. Следующий список — проектные требования; метаданные, счётчик, правила скрытия, отсутствие перехвата фокуса и выбор монитора ещё не проверены в оригинале:

- работает без открытия главного окна;
- overlay появляется по центру экрана поверх всех окон;
- overlay не крадёт фокус у рабочего приложения;
- текст показывает первые строки и метаданные;
- изображение показывает thumbnail, а не только подпись;
- список файлов показывает имена и количество;
- рядом показывается позиция, например `12 / 50000`, и направление;
- повторная стрелка обновляет существующее окно без мерцания;
- `Esc`, вставка, новое копирование или таймаут скрывают overlay;
- overlay центрируется на рабочей области монитора с активным окном, остаётся поверх остальных окон и не выходит за границы work area.

## 7. Поиск и организация

Проверено: `IncrementalSearch=1`, то есть список фильтруется по мере ввода. Официально подтверждены поиск по содержимому, определение приложения-источника и удаление клипов.

Полная целевая модель:

- поиск по plain text, HTML-тексту, заголовку окна, приложению, URL и именам файлов;
- переход к следующему/предыдущему совпадению;
- фильтр по типу, приложению, времени и ярлыку;
- звёздочка «важное»;
- пользовательские ярлыки/теги, группирующие историю в виртуальные папки;
- удаление одной записи и пакетное удаление;
- защита важных записей от автоматической очистки.

## 8. Шаблоны (snippets)

Вторая вкладка — постоянное хранилище часто используемого текста. Шаблоны организуются в дерево папок, имеют название и содержимое, выбираются мышью либо клавишей быстрого доступа и вставляются в прежнее активное приложение. Активный режим меню шаблонов: `MenuSnippetsMode=2`; число клипов в быстром меню: `MenuCountCHItem=10`.

Операции, которые следует воспроизвести:

- создать, изменить, удалить и переименовать шаблон;
- создать/переместить папку;
- изменить порядок стрелками toolbar или drag-and-drop;
- импорт/экспорт или резервная копия базы шаблонов;
- быстро вставить шаблон без открытия полноценного редактора.

## 8.1. Меню `Файл`

Предоставленные снимки полностью показывают меню `Файл`:

| Команда | Shortcut | Назначение |
|---|---|---|
| Быстрые настройки | подменю | Переключение часто используемых режимов без открытия полного диалога. |
| Настройки… | `F4` | Открывает многостраничный диалог настроек. |
| Заблокировать базу данных | — | Блокирует текущую базу истории; на снимке команда недоступна, вероятно потому, что база не защищена паролем/шифрованием. |
| Заблокировать все базы данных | — | Одновременно блокирует все защищённые базы; также недоступно в текущем состоянии. |
| Свернуть в трей | `Esc` | Скрывает главное окно, оставляя фоновый listener и hotkeys активными. |
| Выход | `Alt+X` | Полностью завершает Clipdiary, мониторинг Clipboard и обработку hotkeys. |

Подменю `Быстрые настройки`:

| Переключатель | Shortcut | На снимке | Назначение |
|---|---|---:|---|
| Следить за буфером обмена | — | включён | Главный pause/resume мониторинга Clipboard. |
| Спрятаться после копирования/вставки | `Ctrl+F2` | включён | Автоматически скрывает основное окно после выполнения действия с клипом. |
| Инкрементальный поиск | `Ctrl+F3` | включён | Фильтрует результаты при каждом введённом символе. |
| Расширенный поиск | `Ctrl+F5` | выключен | Переключает простой поиск на расширенный режим; точный синтаксис требует отдельного снимка/теста. |
| Быстрые клавиши | `Ctrl+F6` | включён | Показывает и активирует буквенно-цифровые shortcuts рядом с клипами и шаблонами. |
| Показывать меню после умного захвата | — | включён | После smart capture открывает меню выбора/действий. Механика самого smart capture на снимках не раскрыта. |
| Поверх всех окон | — | выключен | Делает главное окно topmost. Это отдельно от центрального preview-overlay, который показывается поверх окон при циклическом выборе. |

Для Rust состояния подменю должны синхронно отражаться в полном диалоге. Момент записи конфигурации оригинала не проверен.

## 8.2. Меню `Клип`

Меню применяется к выделенной записи истории. Оно разделяет прямую вставку в ранее активное приложение, восстановление записи в системном Clipboard и операции с самой записью.

| Команда | Shortcut | Назначение |
|---|---|---|
| Вставить в активное окно | `Enter`, `Space`, `Arrow Right` | Временно восстанавливает выбранный клип в Windows Clipboard и вставляет его в окно, которое было активно перед открытием Clipdiary. После операции окно Clipdiary может скрыться согласно настройке. Наличие трёх клавиш позволяет выполнить основное действие без модификаторов. |
| Копировать в буфер обмена | `Ctrl+C`, `Arrow Left` | Делает выбранный исторический клип текущим содержимым Windows Clipboard, но не инициирует вставку и не отправляет клавиши целевому приложению. |
| Напечатать | `Ctrl+Z` | На снимке отключена. Ресурс называет действие `Type in` и содержит задержку печати: речь о вводе текста, не о принтере. Ограничения и Unicode требуют теста. |
| Вставить как простой текст | `Shift+Enter` | Извлекает текстовое представление клипа, отбрасывает HTML/RTF и вставляет только plain Unicode text. Для изображения или файлов команда должна быть недоступна либо использовать текстовое описание — это требует проверки. |
| Копировать как простой текст | `Ctrl+Shift+Insert` | Помещает в Clipboard только plain-text представление без форматирования, не выполняя вставку. |
| Изменить | `F2` | Открывает редактор выделенного клипа. Для текста ожидается редактирование содержимого и метаданных; возможности редактирования изображений требуют отдельного просмотра окна. |
| Удалить | `Ctrl+Delete` | Удаляет выделенный клип из базы истории, вероятно с подтверждением либо возможностью отключить подтверждение. |
| Дополнительно | подменю | Раскрыто на новом снимке; команды и доступность описаны в §8.3. |

### Семантика основных команд

```text
Вставить
  Clipdiary → временно записывает клип в Clipboard
            → передаёт вставку активному окну
            → при включённой настройке возвращает прежний Clipboard

Копировать
  Clipdiary → записывает клип в Clipboard
            → не отправляет вставку
            → выбранный клип остаётся текущим Clipboard
```

Команды `как простой текст` должны использовать сохранённое plain-text представление. Если исходный клип содержит только HTML/RTF, приложение должно безопасно получить из него текст без исполнения разметки, скриптов и внешних ресурсов.

По новому пользовательскому снимку:

| Команда | Клавиши | На снимке | Назначение |
|---|---|---|---|

Визуально это стандартное каскадное меню справа от пункта `Дополнительно`: подписи слева, сочетания справа, недоступные пункты серые, стрелка у `Создать шаблон`. Размер и оформление зависят от DPI и темы Windows.

## 9. Настройки

Окно `Настройки` открывается клавишей `F4`. Это отдельный диалог с фиолетовой строкой заголовка, деревом разделов слева, рабочей страницей справа и кнопками `OK`/`Отмена`. Заголовок текущей страницы показан крупным чёрным шрифтом на жёлтой полосе. Изменения применяются кнопкой `OK`; `Отмена` закрывает окно без их сохранения.

### 9.1. Полное дерево разделов

```text
Общее
Горячие клавиши
└── Мышь
База данных
├── История буфера обмена
└── Шаблоны
Внешний вид
Настройки вставки
Фильтрация
├── Проблемные приложения
├── Проблемные форматы
└── Горячие клавиши
Дополнительно
```

Страница `Дополнительно` теперь полностью показана и описана в §9.11. Для `Внешний вид` пока известны функции из ресурсов, но не текущие значения и геометрия страницы.

### 9.2. Общее

### 9.9. Фильтрация → Проблемные форматы

Clipdiary перечисляет clipboard-форматы, получение которых может вызывать ошибки, зависания или нежелательные побочные эффекты. Форматы из списка игнорируются, тогда как остальные представления того же клипа могут быть сохранены.

Для будущей Rust-версии этот список является **стандартным blacklist по умолчанию**. Listener обязан проверить имена доступных форматов до чтения данных и не вызывать `GetClipboardData` для совпавших элементов. Совпадение имён зарегистрированных форматов выполняется без учёта регистра, но исходное имя сохраняется в диагностике. Числовые стандартные форматы Windows сопоставляются по их идентификатору, а не только по отображаемому имени.

Список прокручивается. `Добавить` вносит пользовательский формат, `Удалить` удаляет выбранный, `Начальные настройки` восстанавливает заводские исключения Clipdiary. Текущий пользовательский список не доказанно совпадает с заводским; для Rust по запросу пользователя принимается текущий список после уточнения трёх имён.

Правила обработки:

1. Игнорируется только конкретное проблемное представление, а не весь clipboard event.
2. После фильтрации выбираются безопасные альтернативы: `CF_UNICODETEXT`, DIB/DIBV5 или другой проверенный bitmap, `CF_HDROP` и plain-text представление HTML/RTF.
3. `image/png`, `image/jpeg`, `Windows Bitmap` и HTML из blacklist нельзя трактовать как полный запрет изображений или HTML-клипов: одно копирование обычно предоставляет несколько эквивалентных форматов.
4. Если после фильтрации не осталось поддерживаемых представлений, запись не создаётся; в отладочной диагностике фиксируются только имена/ID форматов без содержимого Clipboard.
5. Пользователь может удалить формат из blacklist или добавить собственный. В Rust сброс восстанавливает утверждённый список; атомарность сброса оригинала не проверена.
6. Лимиты размера и ошибки обрабатываются отдельно. У `GetClipboardData` нет аргумента timeout; таймер не прерывает зависший синхронный вызов. Изоляция чтения и watchdog требуют отдельного проектирования, нельзя обещать жёсткий таймаут лишь добавлением async-обёртки.

### 9.12. Центральное превью на новом снимке

Главное окно Clipdiary скрыто. Поверх редактора видно компактное светлое прямоугольное превью приблизительно в центре левого монитора, а не всего виртуального рабочего стола из двух мониторов. Вверху — сообщение о скопированном клипе с позицией `(3)`, ниже — текстовый разделитель, затем содержимое клипа (путь к CopyQ). Системных кнопок закрытия/сворачивания у карточки не видно.

Снимок подтверждает наличие позиции выбранного клипа, но не счётчика вида `12 / 50000` и не индикатора направления. Эти элементы из раннего проектного описания нельзя считать частью оригинала. Физические размеры, точный шрифт, механизм скрытия и правило выбора монитора по уменьшенному снимку не устанавливаются. Второй снимок рабочего стола показывает окно настроек; его нельзя использовать как образец графического Quick Copy preview.

## 10. Хранение и безопасность

Проверенные локальные файлы находятся в `%APPDATA%\Clipdiary`:

- `clipdiary.cfg` — INI-подобная конфигурация;
- `diary.db` — история; на исследованной машине около 5,57 ГБ;
- `snippets.sdb` — база шаблонов;
- `Backup\` — датированные резервные копии шаблонов;
- временные `cli*.tmp`.

Официально заявлено локальное хранение и опциональная защита истории паролем с AES-256. Для аналога рекомендуется SQLite в WAL-режиме, blobs отдельно или в content-addressed store, FTS5 для текста и шифрование всей базы/ключевых полей через проверенную библиотеку. Секреты Clipboard нельзя писать в логи, telemetry или crash dump.

Нужны политика очистки по количеству/возрасту/размеру, транзакционное добавление клипа, дедупликация соседних одинаковых записей и восстановление после аварийного завершения.

## 11. Трей и жизненный цикл

- Один экземпляр приложения; второй передаёт команду первому.
- Закрытие главного окна скрывает его, но мониторинг продолжается.
- Значок трея открывает историю и предоставляет быстрое меню последних клипов/шаблонов.
- Можно временно приостановить мониторинг.
- Выход через меню/трей завершает listener, сбрасывает очередь записи и снимает глобальные hotkeys.
- Обновление настроек применяется без перезапуска, если возможно.

## 12. Фильтры и исключения

Нужны два разных механизма:

1. Не записывать Clipboard, если источником является исключённое приложение (менеджеры паролей, приватные окна и т. п.).
2. Игнорировать горячие клавиши в приложениях из отдельного списка. Это не доказательство запрета вставки из меню или команды копирования.

Формат путей, регистр и поддержка wildcard требуют проверки. Символ `*` между путями в CFG может быть разделителем списка, а не шаблоном. Режим «не сохранять следующий клип» пока не подтверждён в Clipdiary.

## 13. Рекомендуемая архитектура Rust

- `clipboard_listener`: скрытое Win32-окно, `AddClipboardFormatListener`; задержка захвата отдельна от вставки. Ресурс Clipdiary указывает default 20 мс, а 200 мс на пользовательском снимке относится к вставке. Debounce не должен незаметно отбрасывать быстрые копирования.
- `capture`: чтение всех поддержанных форматов с повторными попытками при занятом Clipboard.
- `model`: `Clip`, `ClipFormat`, `SourceApp`, `Tag`, `Snippet`, стабильные UUID/ID.
- `storage`: SQLite/FTS, миграции, лимиты, backup, blob store.
- `hotkeys`: глобальная регистрация, настраиваемые chords, машина состояния Previous/Next.
- `paste`: сохранение целевого HWND, восстановление форматов, синтетический `Ctrl+V`, защита от повторного захвата собственного clipboard update.
- `ui`: главное окно, виртуализированный список для 50 000+ записей, editor, settings.
- `preview_overlay`: отдельное top-level no-activate окно для текста/bitmap/file list.
- `tray`: single-instance IPC, меню, pause/exit.

Главный технический риск — не UI, а корректная работа с Windows Clipboard: delayed rendering, owner/source HWND, несколько форматов одной записи, заблокированный clipboard, DPI/multimonitor и исключение собственных изменений из истории.

## 14. Приёмочные сценарии будущей реализации

1. При скрытом главном окне скопировать A, B, C; пройти назад до A и вперёд до C. Каждый шаг показывает верное текстовое превью по центру поверх всех окон, не открывает главное окно и не забирает фокус.
2. Между A и C скопировать изображение; при циклическом выборе центральный always-on-top overlay показывает именно bitmap с правильными пропорциями.
3. Вставить HTML в Word/браузер и plain text в Блокнот из одной записи.
4. Скопировать несколько файлов и восстановить их как `CF_HDROP`.
5. Скопировать пустую строку, 10 МБ текста, прозрачный bitmap и очень широкое изображение.
6. Копировать быстро 100 раз; порядок не теряется, UI не блокируется.
7. Clipboard временно занят другим процессом; выполняются retry/backoff без зависания.
8. Источник в denylist не сохраняется.
9. Перезапуск сохраняет историю, выделение и геометрию окна.
10. Два монитора с разным DPI: окно и overlay остаются в work area.
11. Удаление, поиск, теги, important и шаблоны переживают перезапуск.
12. Вставка скрывает окно и возвращает фокус точному исходному HWND.
13. Собственная операция восстановления Clipboard не создаёт дубликат.
14. Парольная база не открывается с неверным ключом и не оставляет plaintext во временных файлах.

### 17.3. Отслеживание Clipboard в Windows

Архитектура Rust-версии на основе изученного поведения:

1. Создать отдельный STA-поток с невидимым Win32 message-only window.
2. Зарегистрировать окно через `AddClipboardFormatListener`.
3. Обрабатывать `WM_CLIPBOARDUPDATE`, но перед чтением сравнивать `GetClipboardSequenceNumber()` с последним обработанным номером.
4. Сразу сохранить HWND foreground/owner и сведения о процессе, пока пользователь не переключился на другое окно.
5. Поставить событие в debounce/retry-очередь; не читать тяжёлые форматы непосредственно внутри window procedure.
6. Открывать Clipboard с ограниченными повторными попытками и backoff, потому что другой процесс может временно удерживать его открытым.
7. Сначала перечислить форматы, применить blacklist проблемных форматов и privacy markers, затем скопировать разрешённые данные в собственную память.
8. После успешного clone сравнить payload с последней записью и не создавать бессмысленный соседний дубликат.
9. Передать immutable `CapturedClip` в поток хранения; никогда не сохранять borrowed handles из Clipboard.

Проверка sequence number нужна дважды: уведомления могут дублироваться, а Clipboard способен измениться прямо во время чтения. Если номер изменился между началом и завершением capture, результат отбрасывается и событие читается заново.

### 17.4. Privacy и запрет мониторинга

CopyQ учитывает стандартные и распространённые маркеры, которые необходимо поддержать в rustclip:

```text
Clipboard Viewer Ignore
ExcludeClipboardContentFromMonitorProcessing
CanIncludeInClipboardHistory = DWORD 0
CanUploadToCloudClipboard = DWORD 0
ExcludeClipboardContentFromMonitorProcessing = "1"
```

В изученном CopyQ эти маркеры ведут к пометке `mimeSecret` и отдельному callback. Это не доказывает, что CopyQ вообще не читает данные: `DummyClipboard::data` вызывает `cloneData` и затем добавляет признак секрета.

В Windows `CanUploadToCloudClipboard=0` запрещает облачную синхронизацию, но не локальную историю; запрет локальной истории задаётся отдельно. Более строгая политика CopyQ — его собственное решение, а не требование Windows. Для Rust предлагается не сохранять маркеры запрета мониторинга/истории; политику для одного лишь запрета облака следует определить отдельно. [Microsoft: Clipboard formats](https://learn.microsoft.com/en-us/windows/win32/dataxchg/clipboard-formats#cloud-clipboard-and-clipboard-history-formats).

### 17.5. Подавление собственных обновлений

Одного булевого `ignore_next` недостаточно: между записью приложения и уведомлением может вклиниться чужое изменение. Ниже предложен транзакционный маркер Rust. Это не описание CopyQ: его `anySessionOwnsClipboardData` проверяет наличие `mimeOwner`, а не совпадение UUID операции.

- перед `SetClipboardData` генерировать случайный operation UUID;
- добавлять собственный зарегистрированный формат `RustClip/Owner` со UUID операции;
- хранить ожидаемую операцию, sequence number после закрытия Clipboard и hash основного payload;
- при `WM_CLIPBOARDUPDATE` считать изменение собственным только при совпадении marker/UUID;
- собственное временное изменение при вставке не добавлять в историю;
- внешнее изменение никогда не подавлять лишь потому, что оно пришло «следующим».

Маркер следует удалять из экспортируемой постоянной модели клипа и не передавать в приложения там, где он не нужен.

### 17.6. Multi-format capture

Модель CopyQ подтверждает важный принцип: клип — это карта `format → bytes`, а не только строка или картинка. Rust-модель:

```text
CapturedClip
├── sequence_number
├── captured_at
├── source { hwnd, pid, executable, title }
├── representations[]
│   ├── format_id
│   ├── registered_name?
│   ├── bytes / normalized value
│   └── size
├── searchable_text?
├── preview?
└── content_hash
```

Читать только whitelisted представления и вводить лимиты на один формат и весь клип. Синтезировать нормализованный plain text/preview отдельно, не уничтожая оригинальные RTF, HTML, DIB или `CF_HDROP`.

### 17.7. Вставка

Предлагаемый pipeline Rust (не весь алгоритм подтверждён в CopyQ; восстановление прежнего Clipboard с защитой от гонки — проектное решение):

1. До открытия Clipdiary/overlay сохранить точный целевой `HWND`.
2. Проверить, что окно ещё существует, видимо и принадлежит ожидаемому процессу.
3. Дождаться отпускания `Ctrl`, `Shift`, `Alt`, `Win`; иначе пользовательский hotkey смешается с синтетической вставкой.
4. При включённом восстановлении клонировать текущее содержимое Clipboard в память.
5. Записать выбранный multi-format clip вместе с owner operation UUID.
6. Закрыть Clipboard и выдержать настраиваемую compatibility delay.
7. Вернуть окно на передний план через `SetForegroundWindow`; при необходимости кратковременно использовать `AttachThreadInput`, после чего обязательно отсоединить потоки.
8. Послать полный key-down/key-up пакет через `SendInput`.
9. В исследованном CopyQ `pasteWithCtrlV` выбирает `Ctrl+V` при совпадении настройки/regex, иначе используется `Shift+Insert`. Clipdiary имеет свой переключатель. Rust должен воспроизводить выбор Clipdiary, не наследуя автоматически defaults CopyQ.
10. После небольшой задержки восстановить прежний Clipboard новым отмеченным owner-operation, только если Clipboard всё ещё содержит вставляемый нами payload. Если пользователь успел что-то скопировать, восстановление отменяется.

Последний пункт защищает от потери пользовательского копирования, случившегося во время вставки.

### 17.8. Эмуляция копирования

Для команды захвата из активного окна:

1. Запомнить текущий `GetClipboardSequenceNumber()`.
2. Вернуть фокус целевому HWND.
3. Послать `Ctrl+C` через `SendInput`.
4. Ждать изменения sequence number с таймаутом около 2 секунд, обрабатывая message loop.
5. Успехом считать только фактическое изменение Clipboard.

Rust-реализация не должна блокировать UI-поток busy-loop: ожидание выполняется асинхронно по `WM_CLIPBOARDUPDATE` с timer deadline.

### 17.9. Что переносим, а что нет

Переносим как требования/архитектурные идеи:

- sequence-number deduplication;
- notification-driven listener;
- multi-format clips;
- privacy markers;
- owner marker для собственных операций;
- retry/backoff чтения;
- ожидание отпускания модификаторов;
- надёжный фокус + полный `SendInput` key sequence;
- выбор paste shortcut для проблемных приложений;
- проверку фактического изменения после synthetic copy.

Не переносим напрямую:

- Qt-типы (`QClipboard`, `QMimeData`, signals/slots);
- CopyQ IPC, scripting engine, plugin ABI и модель вкладок, если они не нужны Clipdiary-паритету;
- GPL-исходники и их структуру без явного решения лицензировать rustclip совместимо с GPL.

### 18.3. Поправки к техническим предположениям

- В CopyQ `cloneData` не безусловно сохраняет все представления: в перегрузке с заданными форматами при доступном тексте пропускаются бинарные картинки, чтобы не заставлять источник рендерить огромную таблицу. Картинки читаются последними. Это стратегия CopyQ, а не обязательная стратегия rustclip.
- UUID на каждую вставку, bounded retries, no-activate overlay и защищённое восстановление Clipboard — проектные предложения. Они не были обнаружены как готовое ядро в показанных функциях CopyQ.
- Windows не обещает автоматически переводить произвольный `image/png` в DIB. Если источник даёт только исключённый формат, картинка будет потеряна для истории; необходим тест браузера, Snipping Tool и файлового менеджера.
- Registered `HTML (HyperText Markup Language)` нельзя автоматически приравнивать к стандартному для CF_HTML имени `HTML Format`; аналогично `Windows Bitmap` не равен `CF_BITMAP`. Blacklist должен сопоставлять точное имя/ID, не целый смысловой класс.
- Bitmap handle нельзя универсально обрабатывать как HGLOBAL с байтами. Нужен обработчик каждого поддерживаемого семейства. Данные копируются до закрытия Clipboard; системные handles не освобождаются приложением. [Microsoft: GetClipboardData](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getclipboarddata).
- Успех `SendInput` не доказывает, что приложение уже прочитало Clipboard. Проверять нужно число отправленных событий, фокус, права процесса и фактическую вставку. Обычная задержка не гарантирует безопасное восстановление для любого приложения.
- Обещание сохранить все 100 очень быстрых копирований слишком сильное: Windows Clipboard содержит только текущее значение; при отставании listener промежуточные состояния могут быть недоступны. Тест должен измерять пропуски, а не предполагать их невозможность.

### 18.4. Что нужно показать/проверить для завершения документации

Приоритет 1 — повседневная работа и визуальный паритет:

1. Закрыто новыми снимками: `Дополнительно`, текущие значения записаны в §9.11.
2. Страница `Внешний вид` целиком.
3. Закрыто новыми снимками: полная страница `Горячие клавиши`, включая auto-paste и plain-text команды (§9.3).
4. Текстовое центральное превью показано (§9.12), таймеры известны. Остаются графическое превью, скрытие при отпускании клавиш/Esc и правило выбора монитора.
5. Меню `Вид`, `Ярлыки`, контекстное меню клипа и меню трея. `Клип → Дополнительно` уже показано (§8.3); следующий уровень `Создать шаблон` ещё не раскрыт.

Приоритет 2 — редакторы и специальные сценарии:

6. F2 для тестового текста и изображения; создание/редактирование шаблона и окно макросов.
7. Расширенный поиск и множественная вставка.
8. `Действия` для базы истории и базы шаблонов; мастер экспорта; страницы очистки без выполнения удаления.
9. Три обрезанных имени форматов: пользователь сообщил, что уточнить их не получится. Больше не запрашивать. Сохранять их как кандидаты; не превращать обрезанные строки в wildcard и не включать восстановленные догадкой имена в проверенный blacklist. Остальные точные имена остаются обязательными исключениями Rust.
10. `Помощь` и About — для полноты карты окон.

Поведенческие вопросы, на которые достаточно ответить словами:

- Auto-paste включён по снимку; дополнительного вопроса о состоянии переключателя не требуется. Фактический момент вставки следует проверить в тестовом поле.
- Таймер Quick Copy равен 0: автоскрытия по времени нет. Остаётся проверить исчезновение при отпускании Ctrl/Shift, вставке и Esc.
- После достижения самого нового/старого клипа стрелка останавливается или начинает круг?
- Обычный Ctrl+V после вставки из истории вставляет выбранный исторический клип или содержимое, которое было до этого?

Точные алгоритмы дедупликации, экспорт, очистка, шифрование и восстановление требуют изолированной тестовой базы. Нельзя объявлять их проверенными по одним названиям кнопок.
